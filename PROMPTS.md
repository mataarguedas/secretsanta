## Rules for every prompt

Every prompt tells Claude to read this section. You don't need to paste it.

1. Before writing code, re-read `CLAUDE.md`, the `PRD.md` sections the prompt cites, and `DESIGN.md` if the prompt touches UI. If the specs conflict, follow the priority order in `CLAUDE.md`.
2. Do **only** what the prompt asks. Don't start the next prompt. If you need something from a later prompt, add the smallest stub that works, mark it `# TODO(prompt N)` / `// TODO(prompt N)`, and mention it in the summary.
3. Never weaken the invariants in `CLAUDE.md` §2 or their tests. Invariant tests can only stay the same or get stricter.
4. Write the tests the prompt lists plus any others the new behavior needs. Run every check that applies and fix problems until they all pass:
   - backend: `uv run ruff check . && uv run ruff format --check . && uv run mypy app && uv run pytest`
   - frontend: `pnpm lint && pnpm typecheck && pnpm test`
5. Every user-facing string goes in **both** `es.json` and `en.json`. Every new error code goes in the `core/errors.py` registry **and** gets `errors.CODE` keys in both locales.
6. If models change, add one Alembic migration per logical change, and review the autogenerated diff before you keep it.
7. UI work must use tokens only (no hex values), no `shadow-*`, and pills for every clickable element. Allow at most one coral primary button per viewport, and check each screen at 320, 768 and 1200 px.
8. Don't add dependencies outside `CLAUDE.md` §3 unless you explain why in the summary.
9. Never log secrets, tokens, cookies, message bodies, assignment pairs or anonymous-member→user mappings.
10. When everything passes, make **one local git commit** with a conventional message (for example `feat(events): create and list events`). Don't push unless I ask.
11. End with a short summary that lists:
    - the files you created or changed
    - the commands you ran and their results
    - anything I have to do by hand (secrets, console setup)
    - known gaps and the TODOs you left

## Before you start (one time)

**Install:**
- Docker Desktop
- Python 3.12 and [`uv`](https://docs.astral.sh/uv/)
- Node 20+ and `pnpm` (`npm i -g pnpm`)
- Git
- Optional: [`exiftool`](https://exiftool.org/), to check that photo metadata is stripped

**Test users.** Most tests need 3–4 different users. Cookies belong to one browser profile, so give each user its own browser:

| User | Browser |
|---|---|
| **A** (host) | your normal Chrome profile, signed in with Google account A |
| **B** | a second Chrome profile, or a Chrome **Guest** window, with Google account B |
| **C** | Edge or Firefox, with Google account C *or* the test login (see below) |
| **D** | another browser or profile, for prompts that need 4 users |

Google only allows accounts that you add as **test users** while the OAuth consent screen is in "Testing" mode (see Prompt 6). If you don't have enough Google accounts, prompt 6 adds a test-only login that works only when the API runs with `ENV=test`.

**PowerShell helper.** Define this once in each terminal. The manual tests call it `dc`:

```powershell
function dc { docker compose -f infra/docker-compose.yml -f infra/docker-compose.dev.yml @args }
```

- Open a database shell: `dc exec postgres psql -U santa -d santa`
- Open a Redis shell: `dc exec redis redis-cli`
- In PowerShell 5.1, `curl` is an alias for something else, so always type **`curl.exe`**.

**Browser console helper.** Paste this into DevTools › Console on `http://localhost:5173` whenever a test says "console":

```js
const api = async (method, path, body) => {
  const r = await fetch('/api/v1' + path, {
    method, credentials: 'include',
    headers: { 'Content-Type': 'application/json', 'X-Requested-With': 'fetch' },
    body: body ? JSON.stringify(body) : undefined,
  });
  const text = await r.text(); let data; try { data = JSON.parse(text); } catch { data = text; }
  console.log(r.status, data); return data;
};
```

**Where things run in development:**

| Service | Address |
|---|---|
| Frontend (Vite) | http://localhost:5173 (proxies `/api` and `/ws` to :8000) |
| API | http://localhost:8000 |
| MinIO console | http://localhost:9001 |

Always use the app through **:5173**.

## Prompt 6 — Backend auth (Google OAuth, cookies, refresh rotation, `/me`)

> **Do this first, by hand (≈10 min):**
> 1. Go to https://console.cloud.google.com, create a project and open **APIs & Services › OAuth consent screen**. Choose External, keep it in *Testing*, and add Google accounts A, B and C as **Test users**.
> 2. Go to **Credentials › Create credentials › OAuth client ID › Web application**.
>    - Authorized JavaScript origin: `http://localhost:5173`
>    - Authorized redirect URI: `http://localhost:5173/api/v1/auth/google/callback`
> 3. Put `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` in `infra/.env`. Create the JWT secret with `python -c "import secrets; print(secrets.token_urlsafe(64))"` and put it in `JWT_SECRET`.

```text
Read CLAUDE.md §2, §7 (Auth, Rate limits), PRD.md §4.1, §4.9 (FR-ACC-1/2), §7 (users, refresh_tokens), §8, §10 (security) and the "Rules for every prompt" section of PROMPTS.md. This is Prompt 6 (Milestone 2: Auth).

Goal: server-side Google sign-in with secure cookie sessions.

1. Models and a migration:
   - `users`: google_sub, email CITEXT, name, avatar_url, locale, notify_message, notify_wishlist, notify_reminder
   - `refresh_tokens`: user_id, token_hash, expires_at, revoked_at, user_agent

   Follow PRD §7.
2. `app/core/security.py`: create and verify the access JWT (15 min, HS256, `sub` = user id); generate a random refresh token and store only its SHA-256 hash; `safe_next(next)`, which allows only relative paths (must start with a single "/", no "//", no scheme, no backslash, no control characters) and otherwise returns "/".
3. `app/api/auth.py`:
   - `GET /auth/google/login?next=`: Authlib, Authorization Code + PKCE, state kept in a short-lived signed cookie or session
   - `GET /auth/google/callback`: exchange the code; upsert the user from the Google profile (on first sign-in, locale comes from Accept-Language: `en` if it starts with en, otherwise `es`); set cookies; redirect to `APP_BASE_URL + safe_next`
     - `access_token`: httpOnly, SameSite=Lax, Secure from `settings.cookie_secure`, path "/"
     - `refresh_token`: httpOnly, SameSite=Lax, Secure, path "/api/v1/auth"
   - `POST /auth/refresh`: rotate. Revoke the old token and issue a new pair. If a revoked token is presented again, revoke **all** of that user's tokens (reuse detection). Returns 401 `AUTH_REFRESH_INVALID` on failure.
```

## Prompt 14 — The pure draw module

```text
Read CLAUDE.md §7 (Draw), §9, PRD.md §4.4, §4.5, §6 and the "Rules for every prompt" section of PROMPTS.md. This is Prompt 14 (Milestone 4: Exclusions & draw).

Goal: `app/services/draw.py`, a **pure** module (no I/O, no DB, no logging of pairs).

1. Generic over a hashable participant id type `T`:
   - `is_feasible(participants: Sequence[T], exclusions: Iterable[tuple[T, T]]) -> bool`
   - `draw(participants: Sequence[T], exclusions: Iterable[tuple[T, T]], rng: random.Random) -> dict[T, T]`

   Exclusions are symmetric. Self-pairs are always forbidden.
2. Feasibility: build the bipartite "givers × receivers, edge when allowed" graph and run **Hopcroft–Karp**. A perfect matching means feasible.
3. Draw:
   - shuffle the givers with the injected RNG
   - for each giver, try receivers in RNG-shuffled order, and before committing check with the matching algorithm that the remaining subgraph still has a perfect matching (pruning)
   - up to 1000 restarts
   - raise `DrawInfeasibleError` when infeasible, and `ValueError` when n < 3 or there are duplicate ids

   A single cycle is not required.
4. Tests (`tests/unit/test_draw.py`):
   - Hypothesis property tests with random n (3–40) and random exclusions filtered to feasible cases: the result is a bijection, has no self-pairs and has no excluded pair (both directions)
   - when `is_feasible` is false, `draw` raises
   - fixtures: 3 people where one is excluded from both others → infeasible; a "nuclear family" (4 family members all mutually excluded plus 4 others) → feasible, and the draw respects it
```
